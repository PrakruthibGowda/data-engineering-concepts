## Extract, Load and Transform

<p align='centre'> Extract, Load and Transform means data is first pulled from source systems and loaded directly into the target storage system in its raw form. 
  The transformations are then performed inside the data warehouse or data lake using its compute power. 
  This approach is common in modern cloud architectures where storage and compute are scalable and relatively inexpensive. </p>

### Extract

  * Data is pulled from source systems.

  * Sources – Common sources include relational databases, application logs, APIs, event streams (Kafka), SaaS platforms, and IoT devices.

  * Methods – Data can be extracted in batches, incrementally using timestamps or change data capture (CDC), or streamed in real time.

### Load

  * Data is loaded immediately into the target system before transformation.

  * Targets – Data warehouses like BigQuery, Snowflake, Redshift, or data lakes like S3, Azure Data Lake, GCS.

  * Strategy – Raw data is typically stored in a staging or raw layer (sometimes called the bronze layer). Data is appended as-is to preserve original records.

### Transform

  * Transformations happen inside the data warehouse or lakehouse after loading.

  * Common transformations – Filtering, aggregations, joins, type casting, deduplication, enrichment, and building data models (fact and dimension tables).

  * Tools – SQL transformations, dbt, warehouse-native tools (BigQuery SQL, Snowflake tasks), Spark on Databricks, or materialized views.

### Why Use ELT and When?

  * When using modern cloud data warehouses that provide powerful compute and scalable storage.

  * When raw data needs to be retained for reprocessing or auditing.

  * When business logic changes frequently, allowing transformations to be modified without re-extracting data.

  * When faster development and iteration cycles are needed.

  * When multiple teams (analytics, ML, BI) may need different transformations from the same raw data.
    
### When NOT to Use ELT

Avoid ELT when:

  * Sensitive data must be masked or filtered before storage due to compliance or regulatory requirements.

  * The warehouse cannot store large volumes of raw data.

  * Transformations must happen before data reaches the destination system.

  * Source systems produce extremely large raw data where pre-aggregation is required to reduce volume.

### Example: E-commerce Analytics Pipeline (ELT)

Imagine an e-commerce company that wants to analyze customer behavior, revenue, and product performance.
The company has multiple operational systems:

  * Website transactions database

  * Payment provider (Stripe)

  * Marketing platforms (Google Ads, Facebook Ads)

  * Customer support tool (Zendesk)

Instead of transforming data before loading, the company loads raw data first into a cloud warehouse and performs transformations there.

    Operational Databases / SaaS APIs (Extract (Fivetran / Airbyte / CDC))
       -->
    Raw Tables in Data Warehouse (BigQuery / Snowflake)
       -->
    Analytics Tables (Fact & Dimension Models) (Transform using SQL / dbt)
       -->
    Dashboards / BI Tools / ML Models
